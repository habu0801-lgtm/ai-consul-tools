# cost-management-tool（事例紹介）

飲食店向けの **食材原価管理ツール**（スプレッドシート5シート構成 ＋ GAS連携）の制作事例です。

> **本ページは事例紹介です。**
> 原価率・仕入れ単価・出数・損益額といったクライアント企業様の経営数値は、
> 許可の有無にかかわらず**一切公開していません**。シート実物およびソースも非公開です。
> ここに残すのは、設計上の判断と、そこで踏んだ地雷だけです。

## 課題

- 仕入れ価格が**月中でも変動する**（同一伝票内で同じ食材が2種類の単価で入荷していた実例あり）
- にもかかわらず、販売価格の改定判断が**手動・感覚依存**だった
- 原価率の把握ラグが、そのまま利益漏れになっていた
- 月間仕入れ規模が大きく、数％のズレでも金額インパクトが出る

## 作ったもの

仕入れ単価が変われば、**原価・原価率・目標との差・適正販売価格・値上げアラートが自動で再計算される**
スプレッドシート。5シート構成。

| シート | 役割 |
|---|---|
| サマリー | 要確認件数・全体原価率（出数で重み付け）・原価率ワースト5を1画面に集約 |
| 原価管理 | メニュー別の原価・原価率・適正販売価格・3段階判定 |
| 食材マスタ | 仕入れ品目とメニューを結ぶ中間層。採用単価を決める |
| 仕入れ履歴 | 伝票を追記する台帳。前回単価との増減を表示 |
| 設定 | 目標原価率・税率などを1箇所で管理 |

さらに **Googleフォーム＋GAS** で、伝票をその場でスマホ入力 → 仕入れ履歴に自動追記 → 原価率まで一気に更新
できるようにしました。

**現在の到達点**: 仕入れ単価・使用量・原価を連動させ、目標との差を一覧で確認できる形にしました。現場への展開後、利用者と入力方法や表示内容をすり合わせ中です。利益改善や作業時間削減の効果は、現時点で数値として掲載していません。

## 設計上の判断（v1 → v8 で潰した問題）

このツールで一番学びが多かったのは、**表計算特有の「エラーにならないバグ」**でした。

### 1. シート間が自動連動していなかった（v2）

初版最大の欠陥。仕入れ履歴に新単価を記録しても、原価管理シートの単価が**自動更新されなかった**。
原因は、履歴側が「仕入れ品目名」、原価管理側が「メニュー名」で、両者を結ぶ紐付けが存在しなかったこと。
結局手打ちが必要で、打ち替え漏れがそのまま判断ミスになる状態でした。

→ **食材マスタを中間層として挟み**、`履歴の最新単価 → 採用単価 → 原価管理の仕入れ単価` と
VLOOKUPで連鎖させて解決。

### 2. IFERRORでは捕まらないバグ（v4）

売っていない食材にまで「適正販売価格」が表示されていました。
原因は `原価 ÷ 目標原価率` が、**売値が空でも計算できてしまう**こと。
数式としては正常に通るので、エラーハンドリングでは検出できません。

→ `IF(売値="", "—", ...)` と**空判定を先に置く**。
同じ型のバグを原価率の列では既に潰していたのに、別の列に残っていたのが原因でした。

### 3. 「最新単価」を行順で判定していた（v4）

食材マスタが「同じ食材名の一番下の行」を最新単価とみなしていました。
フォームで順に追記する分には正しいのですが、**過去データを後から追記した瞬間に壊れる**構造です。

→ 記録日で判定する数式に変更（同日複数入荷なら最下行を採用）。
実際に過去データを追記して検証したところ、旧方式では主力商品の原価率が**実態より低く算出され**、
本来なら値上げ検討対象になるはずの商品を見逃す状態になっていました。

### 4. 「目標値」の意味を取り違えていた（v4）

カテゴリ別の目標値を、**個別商品の合否ライン**として実装したところ、主力商品のほとんどが「要確認」判定になりました。
クライアントに確認したところ、それは**カテゴリをまとめて集計したときの目安**でした。

→ 個別判定は全商品共通の基準に統一し、サマリーに「カテゴリ別の集計値」を新設。
それまで、目標値と比較すべき数字がツール上のどこにも存在していませんでした。
副次効果として、現実離れしていた適正販売価格も検討可能な水準に戻りました。

### 5. 税抜と税込が混在していた（v5）

売値は税込、仕入れ単価は税抜。そのまま比較していたため原価率がずれていました。

→ 仕入れ単価は伝票どおり税抜で持ち、**原価計算時に税率を掛ける**方式に変更（軽減税率8%を初期値、設定シートで変更可）。
これだけで3品の判定が「良好」から「注意」に動きました。

### 6. 主材料だけでは原価を表現できなかった（v5）

タレ・卵などの副材料が原価に入っておらず、実態より低く出ていました。

→ 「副材料」「副材料原価」の列を新設し、食材マスタから単価を引く数式に。
**副材料が値上がりすれば自動で原価に反映**されます。
この修正で、ある商品は判定が「良好」から**「要注意」に変わりました**。
副材料を無視していた分、それまで実態より低く見えていたことになります。

### 7. 加重平均が「各商品1個ずつ」の前提だった（v5）

売れ筋の影響が原価率に反映されていませんでした。

→ 月間出数の列を追加し、**出数で重み付けした原価率**をサマリーの主役に変更。

### 8. 未使用食材の炙り出し（v4）

食材マスタに「使用メニュー数」列を追加し、どのメニューからも参照されていない食材を橙色で表示。
→ 実際に、**あるメニューの原価にタレ代が入っていない**ことがこれで発覚しました。

## 使った技術

Excel / Googleスプレッドシート（VLOOKUP・多段参照・条件付き書式）、Google Apps Script、Googleフォーム。
