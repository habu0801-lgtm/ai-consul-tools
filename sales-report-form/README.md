# sales-report-form

現場スタッフがその場でスマホから接客実績を入力できる、Google Apps Script製の実績報告フォーム。

## 概要

店舗スタッフが顧客対応のたびにスマホからチェックボックスで実績を入力すると、スプレッドシートに自動蓄積される。あとでまとめて手入力する二度手間をなくし、[kpi-reporter](../kpi-reporter) と組み合わせることで「入力→蓄積→週次集計→自動送信」まで一気通貫で自動化できる。

- スタッフ名・獲得項目はホワイトリスト方式でサーバー側検証し、不正な値の書き込みを防止
- `LockService` で同時送信の競合を防止
- 送信前にリアルタイムでサマリー表示し、入力ミスを削減
- 報告者（送信したGoogleアカウント）を自動記録し、あとから追跡できるように

## 構成

```
sales-report-form/
├── code.gs      # サーバー側: 表示・バリデーション・シート書き込み
└── index.html   # クライアント側: 入力フォームUI
```

## 想定シート構成

| シート名 | 役割 |
|---|---|
| 回答ログ | フォームから送信された実績データ（タイムスタンプ・スタッフ名・獲得項目・金額・報告者など） |

`回答ログ`はそのまま [kpi-reporter](../kpi-reporter) の入力ソースとしても使える。

## セットアップ

1. Googleスプレッドシートを新規作成し、拡張機能 → Apps Script を開く
2. `code.gs` / `index.html` の内容を貼り付ける
3. ファイル冒頭の `STAFF_LIST` と `ITEM_LIST` を実際のスタッフ名・獲得項目に書き換える
4. `index.html` 内のプルダウン・チェックボックスも同じ項目名に合わせて編集する
5. デプロイ → ウェブアプリとして公開（実行するユーザー: 自分 / アクセスできるユーザー: 組織内 など）
6. 発行されたURLをスタッフに共有

## なぜGoogleフォームではなくカスタムフォームか

- 1回の入力で複数商材にチェックを入れたい
- 「1接客で最大3件まで」のような数量入力を混在させたい
- 送信前に選択内容をその場で確認させたい
- 入力値をサーバー側で検証し、不正な値がシートに書き込まれるのを防ぎたい

標準のGoogleフォームでは難しいこれらの要件に対応するため、HTMLServiceでカスタムUIを実装している。
